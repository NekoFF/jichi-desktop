# jichi Desktop — контекст для следующего агента

Актуально на 25 сентября 2026 года. Это рабочий бриф **именно для этого
настольного приложения**. Перед изменениями проверь `git status` и текущий код:
часть деталей может измениться. Старый `docs/AUFTRAG_OBERFLAECHE.md` описывает
уже завершённую передачу задач в ветку `design/jlu` и не является новым ТЗ.

## 1. Зачем существует проект

**jichi Desktop** — удобное настольное окно для отдельного AI-агента `jichi`.
Пользователь выбирает папку проекта, пишет задачу, видит ответы, вызовы
инструментов, запросы разрешений и прежние разговоры. Приложение должно
помогать работать с кодом каждый день, а не демонстрировать все возможности
командной утилиты.

Сама модель и агентный цикл находятся в [upstream jichi](https://github.com/alexanderlarsdallmann/jichi).
Этот репозиторий — **клиент**, который запускает бинарник `jichi --acp` как
дочерний процесс и общается с ним по ACP: JSON-RPC 2.0, по сообщению в строке
stdin/stdout. Rust отвечает за процесс, файлы, секрет и системный диалог
выбора папки; TypeScript-ядро — за протокол и состояние; React — за окно.

**Не превращай приложение в графическую копию upstream jichi.** Его GitHub
содержит гораздо более широкий агентный продукт, учебные материалы и roadmap.
Оттуда нужны факты о бинарнике и ACP. Масштаб, структура экранов и визуальные
решения задаются пользователем, текущим приложением и реальными проверками.

## 3. Что уже реализовано

- Первый запуск: имя, скрытый API-ключ, кнопка подключения, короткое сообщение
  о хранении ключа и отчёт `jichi doctor`.
- Один системный Tauri window. Во время настройки реальный интерфейс остаётся
  под затемнением и размытием; форма — HTML-диалог внутри того же окна.
  Второго набора кнопок macOS быть не должно.
- Переключаемые в настройках **Freistehend** и **Klassisch** варианты компоновки.
  Это только внешний вид: поиск, чаты, настройки и возможности должны
  присутствовать в обоих вариантах.
- Светлая, тёмная и системная тема; настройки имени и темы сохраняются локально.
- Поиск по сохранённым чатам, открытие чата, новый чат, **удаление с
  подтверждением**; при удалении активного чата сначала открывается новая
  сессия.
- Выбор папки проекта через системный диалог; папка передаётся агенту как cwd.
- Потоковый текст ответа, карточки инструментов, видимый запрос разрешения,
  отмена хода, ошибки, диагностика и состояние подключения.
- В настройках раздел **Zugang** показывает состояние ключа и умеет его
  удалять. После удаления должен появиться экран первой настройки.
- Ответы агента рендерятся как Markdown (без HTML; ссылки открываются в
  системном браузере, картинки из ответа не загружаются), код подсвечен и
  копируется.
- Запрос разрешения показывает, **что именно** будет выполнено: команду со
  всеми невидимыми символами (␍, ␛, U+202E…) или diff против текущего файла.
  Непарсимые аргументы помечаются как подозрительные.
- Команды агента идут через `terminal/*` приложения — вывод виден в карточке
  в реальном времени (кроме Windows/WSL).
- Выбор модели (из конфигурации и из списка шлюза) и режима Chat/Plan/Auto
  под полем ввода; Auto требует подтверждения и не сохраняется.
- Картинки: вставка, перетаскивание или кнопка — только если модель умеет
  читать изображения.
- Настройки → «Verfügbare Modelle»: что доступно по ключу (только `jlu/…`).
- **Боковая панель справа** (как Artifacts / Canvas / панели Claude Code, план и
  решения — [SEITENPANEL.md](SEITENPANEL.md)): Dateien, Datei (код, Markdown,
  картинки, PDF через pdf.js, Word, Excel/CSV, HTML; правка с проверкой
  конфликта; «An jichi»; «Als Kontext»), Änderungen (git diff, комментарии к
  строкам → jichi, «Code prüfen lassen»), Terminal (настоящий PTY + вкладки
  команд jichi), Browser (дочерний webview, только http/https), Artefakt (HTML,
  SVG, Mermaid, React из блоков кода; песочница `artefakt://`). Пути в ответе,
  карточки файлов и инструментов открывают нужное окно. ⌘⇧E / ⌘⇧D / Ctrl+\` /
  ⌘⇧B / ⌘\\.
- **Чаты:** переименовать (двойной клик/меню), закрепить, удалить; имена и
  закрепления лежат рядом, в `chats.json` приложения (jichi перезаписывает свои
  файлы). Поиск и по содержимому. Экспорт открытого чата в Markdown/Word/PDF.
  Последний чат проекта открывается при запуске. Своё сообщение можно
  «редактировать» (возвращается в поле ввода).
- **Sprungleiste:** слева вверху чата — строки-пиксели по вопросам, эффект
  Dock при наведении, подпись, клик/⌥↑↓ — переход.
- Системное уведомление, если долгий ход закончился или jichi ждёт разрешения
  в фоне. Любой файл можно бросить на окно. «Immer erlauben» в запросе пишет
  `permissions.allow`. В настройках: Erlaubnisse и MCP-Server (вкл/выкл,
  добавить, удалить, «Verbindung prüfen» через `jichi mcp`). ⌘/ — шпаргалка.
- `acp_start`/`doctor`/`probe` запускают только программы с именем `jichi…`.
- `main.tsx` — только оболочка; экраны в `src/ui/`.
- **Документы.** Тот же бинарник, запущенный с `--mcp-dokumente`, — MCP-сервер
  (`src-tauri/src/mcp_dokumente.rs`, `documents.rs`): читает PDF, DOCX,
  XLSX/XLS/ODS, PPTX, ODT, CSV; создаёт DOCX, XLSX, PDF, CSV. Только внутри
  проекта, без перезаписи без `overwrite: true`. jichi берёт MCP-серверы только
  из своего `~/.jichi` (ACP их не передаёт), поэтому переключатель в
  настройках («Dokumente») добавляет/убирает запись `dokumente` с резервной
  копией `~/.jichi.bak-desktop`; новый конфиг из первой настройки получает её
  сразу. Чтение — без запроса (`autoApprove`), запись — с запросом; запрос
  разрешения показывает будущий документ или таблицу. Вложения через «+»
  тоже понимают PDF/Word/Excel. В PDF встроены шрифты DejaVu
  (`src-tauri/fonts/`, лицензия рядом) — только используемые глифы, поэтому
  файлы остаются маленькими; работают немецкий, русский, греческий, ✓ ✗ ⚠ → ≤ €,
  не работают только CJK и цветные эмодзи.
  На Windows jichi живёт в WSL и Windows-бинарник запустить не сможет —
  там сервер пока не подключается.

Список — описание текущего кода, а не гарантия идеальной полировки. Для
поведения, особенно удаления ключа и запросов разрешений, проверяй настоящий
Tauri window. Обычная вкладка `http://localhost:1420` не имеет Tauri bridge:
она может показывать оболочку, но действия с агентом в ней не работают.

### Известные практические ограничения

- Если бинарник `jichi` не найден, форма настройки предлагает выбрать файл
  («Auswählen …»). Домашний поиск принимает только настоящую сборку: рядом с
  файлом должны лежать `include/jc_version.h` и `src/main.c`.
- jichi берёт рабочую папку из **каталога запуска**, а не из `session/new`.
  Поэтому смена проекта (и открытие чата из другого проекта) перезапускает
  агента в новой папке. Пока проект не выбран, агент стоит в `$HOME`, и
  подсказки «Projekt erklären»/«Tests ausführen» отключены.
- Если `jichi doctor` при настройке сообщает ошибки, форма остаётся открытой
  («Erneut prüfen» / «Trotzdem fortfahren»).
- Текущий интерфейс на немецком; не вводи смесь языков без решения пользователя.
- Иконки/кнопки из красивого референса (микрофон, выбор модели, Chat/Work)
  не означают, что соответствующие возможности уже есть в контракте.
  Не добавляй неработающие кнопки ради сходства с картинкой.

## 4. Визуальное направление от пользователя

Это последовательные пожелания пользователя, а не требования GitHub-пакета:

1. Интерфейс должен быть **красивым, минималистичным, аккуратным и работающим**.
   Пользователю понравилась чистая, компактная база, сделанная Claude. Её
   нужно развивать, а не заменять нагромождением новых элементов.
2. Важна плотность настоящего desktop-приложения: небольшие строки, ясная
   иерархия, много воздуха в рабочей области. У upstream дизайн-системы
   крупные компоненты Material 3; они не задают размеры этого окна.
3. На macOS кнопки окна должны быть внутри визуальной области панели, не
   прилипать к её кромке. Не рисуй вторую псевдо-рамку и вторые traffic lights.
4. Лишние логотип и надпись рядом с кнопками окна пользователю не нравятся.
   Одинаковые функции должны быть в обоих вариантах компоновки; тему нельзя
   превращать в два разных продукта.
5. Для **Freistehend**: левая панель — отдельная белая поверхность, справа —
   спокойная, слегка серая рабочая поверхность. Вдохновение: мягкое разделение
   панелей и глубина Telegram. Сохрани возможность выбрать **Klassisch**.
6. Пользователю нравятся умеренные прозрачность, размытие и мягкая объёмная
   тень, особенно у нижней кромки. Это сделано CSS-поверхностями и тенями;
   системная тень macOS добавляется только вокруг всего окна. Эффект стоит
   применять осмысленно, не везде подряд.
7. Первый запуск: одно системное окно; под формой виден настоящий интерфейс,
   достаточно затемнённый и размытый. Сама форма — белая карточка с полями,
   кнопкой и неброской заметкой о ключе. Над ней — отдельная широкая область
   для очень простой абстрактной анимации, похожей по настроению на обои macOS.
   Не возвращай прежнюю «пиксельную» анимацию: пользователь её резко отверг.
   Серый прямоугольник эскиза обозначал **окно**, не дополнительную карточку
   вокруг формы. Актуальный код оставляет форму и верхнюю область без серой
   вложенной рамки.
8. Пользователь просит думать самостоятельно о пропорциях и качестве. Сначала
   проверь существующее поведение и реальные скриншоты, затем меняй точечно.

## 5. Архитектура и границы

| Место | Роль |
| --- | --- |
| `src/main.tsx` | React-компоненты: боковая панель, пустое состояние, переписка, разрешения, настройки, первый запуск. |
| `src/styles.css` | Сетка, плотность, темы через семантические токены, поверхности и анимация. |
| `src/core/index.ts` | Публичный вход для интерфейса: `agent`, `Snapshot`, настройки и подписи. |
| `src/core/agent.ts` | Жизненный цикл агента, сессии, чтение состояния, `setup`, `forgetKey`. |
| `src/core/transport.ts` | Единственное место в TypeScript, где вызывается Tauri. |
| `src/core/state.ts`, `protocol.ts`, `jsonrpc.ts` | Состояние, ACP-типы и JSON-RPC. |
| `src/core/preferences.ts`, `settings.ts` | Локальные предпочтения UI и параметры запуска агента. |
| `src-tauri/src/lib.rs` | Запуск процесса, файловые сессии, выбор папки, секрет и `jichi doctor`. |
| `src-tauri/tauri.conf.json` | **Одно** главное окно, размер и положение системных кнопок macOS. |
| `docs/CONTRACT.md` | Подробный контракт интерфейса с ядром; часть описаний экрана историческая. |

Компоненты пользуются `agent` из `src/core/index.ts`, без прямого `invoke` или
`listen`. `useSyncExternalStore(agent.subscribe, agent.getSnapshot)` читает
снимок состояния. `agent.init()` выполняется при запуске приложения.
`Snapshot.canSend`, `canCancel`, `needsSetup` уже вычисляются ядром; интерфейс
не должен по-своему гадать об их значениях. Для отсутствующей функции добавь
явный метод в ядро и проверь контракт, а не обходи слой транспорта в компоненте.

### Ключ и macOS-диалог

Здесь легко повторить старую ошибку документации: **текущая реализация не
использует macOS Keychain**. Rust хранит ключ в частном каталоге приложения,
в файле с правами `0600` на Unix (каталог `0700`); на macOS это каталог внутри
`~/Library/Application Support/de.uni-giessen.hrz.jichi-desktop/secrets/`.
Интерфейс передаёт новый ключ только через `agent.setup(key)` и очищает поле.
Значение не должно попадать в `localStorage`, React snapshot, логи и git.

Старые файлы ключа из `~/.config/jichi/apikey.txt`, `~/.config/jlu/apikey.txt`
и `~/.jichi-api-key` могут быть однажды перенесены. После явного удаления
ключа приложение ставит маркер, который запрещает повторную автоматическую
миграцию из старого файла. Ранее macOS многократно показывала запрос доступа
к Keychain; именно поэтому текущий код использует собственную защищённую
файловую кладовую. Не возвращай Keychain без отдельного решения.

`JICHI_DESKTOP_DIR=/tmp/...` переопределяет **только каталог приложения** и
удобен для безопасной проверки экрана настройки без изменения настоящего
секрета. Он не переопределяет `~/.jichi` и историю сессий агента.

## 6. Как запустить и проверить

Нужны Node/npm, Rust/Cargo, Tauri v2 и собранный бинарник upstream `jichi`.
На этом Mac он находился в `/Users/neko/FOLDER1HOME/projects/jichi/jichi`.
Приложение ищет его в PATH, обычных `bin` и ограниченным поиском в домашнем
каталоге (глубина 4; системные, скрытые и тяжёлые каталоги пропускаются).

```sh
cd /Users/neko/FOLDER1HOME/projects/jichi-desktop
git status --short
npm install
npm run tauri dev
```

Vite использует порт **1420**. Если он занят, выясни, не работает ли уже
эта dev-сборка, прежде чем запускать вторую. Для проверки настоящего окна
используй Tauri, не одну только вкладку браузера.

```sh
npm run check       # TypeScript + 120 проверок ядра + 20 тестов интерфейса (vitest)
npm run check:rust  # 51 активный тест Rust; ещё 2 требуют агента/сети
npm run build       # сборка фронтенда
```

При последней проверке все три команды завершились успешно. Реальное
подключение зависит от локального бинарника, конфигурации и доступа к серверу;
не обещай его по одним только unit-тестам. Не печатай ключ в командах,
скриншотах и логах.

## 8. Следующий шаг для агента

Сначала просто восстанови контекст: прочитай этот файл и `git diff`, открой
Tauri-окно, сравни его с сохранёнными ориентирами. Если пользователь просит
доработку — реализуй именно её, сохрани оба layout-варианта и все функции,
проверь сборку и взаимодействие в настоящем окне. Отдельно называй то,
что проверено кодом, тестом и вручную: это разные уровни уверенности.
